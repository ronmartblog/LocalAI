1 · Overview

LocalAI Studio generates images entirely on your local machine using ComfyUI as the generation backend. There are no cloud services involved, no API keys required, and no usage fees — every inference runs on your local GPU.

Because everything stays on-device your prompts, reference images, and generated outputs never leave your computer. Privacy is absolute.

ComfyUI is lazy-started by LocalAI Studio. Generate, Analyze→Prompt, and Restart start or restart it when needed. The status of the ComfyUI process is shown at the bottom of the sidebar — a green “Connected” indicator means you are ready to go. If ComfyUI is not running, use the Restart button in the status bar (described in the next section) to start it.

Before you start

Make sure at least one image model is downloaded. If the Model dropdown is empty, visit the Models tab and download a model first. SD 1.5 (2 GB) or Flux Schnell Q4 (6.6 GB) are good starting points.

2 · ComfyUI Status Bar

The status bar at the bottom of the sidebar shows the live state of the ComfyUI process at all times. It also hosts two action buttons.

Connected — N checkpoint(s) available
ComfyUI is running and has detected N model files. The Model dropdown is populated and you can generate immediately.
Checking…
The app is performing its startup probe — polling the ComfyUI API to confirm it is responsive. This normally resolves within a few seconds of launch.
Not running
The ComfyUI process has stopped, crashed, or was never started. Click Restart to relaunch it.

Action Buttons

Restart Button

Kills the existing ComfyUI process (if any) and relaunches it from scratch. Use this if ComfyUI crashes, hangs, stops responding to generation requests, or if you have manually added new model files and want the dropdown to refresh. The restart typically takes 5–15 seconds; status will cycle through Checking… before returning to Connected.

Free VRAM Button

Calls ComfyUI’s /free endpoint, which unloads the currently loaded model from GPU memory without restarting the process. This is useful when you want to switch to a significantly larger model — for example, moving from Flux Schnell Q4 to Flux Dev FP16 — and you want to reclaim the VRAM that the previous model is occupying before the next generation loads the new one. You do not need to use this for normal model switching; it is only necessary when VRAM is tight.

3 · Model Selection

What is a Checkpoint?

A checkpoint is a file that contains all of the trained weights for a diffusion model — think of it as the "brain" of the image generator. Everything the model has learned about shapes, textures, lighting, faces, and artistic styles is stored inside this single file. Swapping the checkpoint is like swapping the artist: the same prompt can produce dramatically different results depending on which checkpoint is loaded.

File Formats

  • .safetensors — The standard, safe format used by most modern checkpoints. Files are memory-mapped directly into the GPU, so loading is fast and there is no code-execution risk.
  • .gguf — A quantized format used primarily by Flux models. Quantization compresses the weights (e.g. to 4-bit or 8-bit integers) so the file is smaller and requires less VRAM, at a small cost in quality. If you see a Flux model listed as .gguf, it is a quantized variant.

Model Families

  • SD 1.5 — The original Stable Diffusion architecture. Runs well on low-end hardware (4 GB VRAM), generates at 512×512, and has a massive library of fine-tunes and LoRAs. Best for fast experimentation or machines with limited GPU memory.
  • SDXL — A larger, more capable architecture that natively generates at 1024×1024. Produces significantly more detailed and photorealistic results than SD 1.5 but requires at least 8 GB VRAM. Models like Juggernaut XL v9 and Playground v2.5 are SDXL fine-tunes.
  • Flux — The newest generation of open-source diffusion models (by Black Forest Labs). Flux models excel at prompt adherence and photorealism. The Schnell variant generates in as few as 4 steps; the Dev variant is slower but higher quality. Flux models require 10–12 GB VRAM; the .gguf quantized builds run in 6–8 GB.
  • Z-Image — A newer DiT-style family with a Qwen text encoder. Z-Image Turbo is distilled for short, high-quality runs, uses CFG 1.0, and is best treated like Flux: natural-language prompts, 1024×1024, and no negative prompt box.
  • Chroma — A Flux-architecture family focused on painterly color fidelity and detailed artistic realism. Chroma checkpoints can contain "flux" in their filenames, so LocalAI detects Chroma before generic Flux and prepares its custom support node before generation.

The "In VRAM" Indicator

Next to the Model dropdown you may see an In VRAM label. This shows which checkpoint is currently loaded in GPU memory. Loading a checkpoint for the first time can take 10–30 seconds and temporarily spikes GPU memory use. Once loaded, subsequent generations with the same checkpoint are fast because the weights are already on the GPU. If you switch to a different checkpoint, the old one is evicted and the new one is loaded before the next generation begins.

VRAM tip: Larger checkpoints consume more GPU memory and leave less room for the latent canvas and attention maps. If you run out of VRAM mid-generation (which causes an error or a black image), try switching to a smaller or quantized checkpoint, or reduce the output resolution in the Size field.

The Model dropdown lists every .safetensors or .gguf checkpoint file that ComfyUI has detected in its models/checkpoints/ and models/diffusion_models/ directories. Selecting a model does two things: it tells LocalAI Studio which checkpoint to load on the next generation, and it automatically configures optimal defaults for all other settings.

4 · Analyze Reference Image → Prompt (img2prompt)

👁
One-click prompt generation from any photo
Powered by the selected local vision model — Gemma 3, MiniCPM-V, Llama 3.2 Vision, and other catalog vision models can run 100% locally

The Analyze → Prompt feature lets you point the app at any reference photograph and have a vision AI instantly generate a detailed, model-ready positive prompt. It is the fastest way to recreate a look you love without having to manually describe every element of the image.

How it works

  1. Click Browse… next to the Reference: label and select a photo (.png, .jpg, or .jpeg).
  2. A thumbnail preview of your selected image appears directly in the UI.
  3. Click Analyze → Prompt.
  4. The selected vision model analyzes the image in detail and generates a comprehensive, comma-separated positive prompt.
  5. The generated prompt is automatically inserted into the Prompt textbox — ready to use immediately, or edit as needed.

What the vision model analyzes

The model is instructed to examine every visible element of the image and translate it into photographic vocabulary that SDXL and Flux models understand well. This includes:

  • Subject — appearance, pose, expression, clothing details, accessories
  • Setting and environment — location, architectural elements, natural features, time of day
  • Lighting — quality (hard/soft), direction, color temperature, catch lights in eyes, shadow fill
  • Camera perspective — focal length equivalent, shooting angle (eye-level, low angle, aerial), depth of field
  • Artistic style — photorealistic, cinematic, illustrated, editorial, documentary, etc.
  • Color palette and mood — dominant hues, saturation, contrast, overall emotional tone

Prerequisites

Vision model required

A compatible local vision model, such as Gemma 3, MiniCPM-V, or Llama 3.2 Vision, must be installed for this feature to work. If it is not installed, the Analyze → Prompt button will be disabled and a Get Model button will appear next to it. Click Get Model to download it directly from the Image Gen page, or go to the Models tab, filter by Large, and click Get Model on the Llama 3.2 Vision 11B card. Once downloaded, the button activates automatically — no restart needed.

Tips for best results

Analyze → Prompt tips

  • Use a reference as close as possible to your target look. The closer the reference is to what you want, the less editing the generated prompt will need.
  • Concise, tag-based output. The vision model generates 15–25 comma-separated tags (up to ~120 tokens). Edit or extend the result as needed before generating.
  • Edit after generating. The prompt is a starting point, not a final answer. Remove terms that don’t apply to your intent, and add specifics about things the image doesn’t show but that you want.
  • Best paired with photorealistic SDXL models. Juggernaut XL v9, SDXL Base, and Playground v2.5 respond well to photographic vocabulary — exactly what the vision model generates.
  • Works with any subject. Portraits, landscapes, products, architecture, food — the vision model has broad knowledge and will adapt its description vocabulary to the content type.

5 · Reference Image Generation (img2img)

Use Reference Image for Generation tells the SD or SDXL model to start from your photo instead of pure noise. The result keeps the composition, colors, and overall structure of the reference, then restyles it according to your prompt. This is the right tool for “same pose, same scene, different lighting” or “keep this composition but turn it into an oil painting”.

Not for identity-preserving portraits

Reference Image Generation preserves composition, not identity. Faces will resemble the reference loosely but will not be the same person. The SD/SDXL img2img pipeline blends the reference image with your prompt at the denoise strength you pick — it is not a face-locking workflow, and there is no way inside LocalAI Studio to pin the subject’s identity to a specific input photo.

Where it is

Under the model picker on the Image Gen page, check “Use reference image for generation”. The checkbox is only enabled for SD 1.5 and SDXL family models (Juggernaut, SDXL Base, Playground v2.5, Realistic Vision, SDXL Lightning, etc.). FLUX, Z-Image Turbo, and Chroma do not support reference-image generation in LocalAI — the checkbox will read “Reference image generation not supported by this model” when one of those is selected.

Ticking the box also auto-populates the positive and negative prompt fields with a documented reference-image sample (the default selection of the Prompt builder below), so your very first generation works without typing anything. Switching to a different SD/SDXL checkpoint while the box stays ticked re-applies the same sample, so you always start from a known-good ref-image prompt. Unticking the box restores the selected model’s normal demo prompt + default negative.

Prompt builder

You don’t need to use this builder for the default sample — ticking the “Use reference image for generation” checkbox already loads it. Use the dropdowns below only when you want a variation: a woman instead of a man, a different age, different lighting, or different clothing. Click Copy positive to put the result on your clipboard, then paste it into the Image Gen page’s positive prompt box; click Copy negative to do the same for the negative prompt box.

The fixed tokens at the end of the prompt — sharp focus, photorealistic, detailed skin texture, 8k — stay locked because they are what makes the sample reliably photorealistic on every SD/SDXL checkpoint. The Strength slider below is the bigger lever for style changes.

The four basic dropdowns are enough for most jobs. Open Advanced refinements below them when you want to layer in expression, environment, composition, camera/lens flavour, color grade, skin treatment, facial-hair guards, or your own custom add/avoid phrases. Every advanced field starts at “Unspecified” so leaving them alone keeps the output identical to the auto-loaded sample.

Match reference aspect (recommended)

  

    The Match reference aspect checkbox under the slider
    automatically snaps the output width and height to the closest standard
    bucket for the reference photo’s aspect ratio at queue time. This
    fixes the most common failure mode: when the reference is a
    9×16 portrait and the target is 1024×1024 square, the
    workflow center-crops the reference — cutting the subject’s
    head out of the frame. With aspect-match on, a 9×16 reference
    becomes 768×1344, a 16×9 becomes 1344×768, and a
    2×3 becomes 832×1216 — all standard SDXL buckets the
    refiner was trained on.
  

  

    Turn it off if you want to deliberately re-frame the composition
    yourself (e.g., square crop of a portrait reference).
  


  
Lightning / Turbo and reference images

  

    Four-to-eight step fast checkpoints (SDXL Lightning, SDXL Turbo,
    Z-Image Turbo’s SDXL siblings) cannot recover from high-denoise
    noise — the output turns to mush above ~0.85. LocalAI silently
    clamps the strength to 0.85 in that case and notes it once in the
    progress strip, so the reference is preserved even if your slider
    happens to be all the way up.
  


  
Tips

  
    
    
  • Start at 0.55, adjust from there. If the reference is too
    dominant, raise it; if your prompt isn’t showing up at all, raise it.
    If the reference is being ignored, lower it.
    • 
    
  • Composition over content. Reference Image Generation is
    about pose, framing, and color — not about preserving a person’s
    face. Faces drift toward whatever the prompt describes; there is no
    face-locking workflow in LocalAI Studio.
    • 
    
  • Pair with Analyze → Prompt. Run Analyze → Prompt
    on your reference first to get a baseline description, then refine it
    before generating — the two features compose well.
    • 
    
  • Use the same aspect as your reference. Leave
    “Match reference aspect” on unless you specifically want a
    different crop.

6 · Prompting

  

    
Need a wow demo prompt?

    
Open Image Gen Prompt Ideas for model-specific, click-to-copy prompts that match the image model you are demoing.

  


  
Positive Prompt


  
The positive prompt describes what you want to appear in the image. The
  ideal prompt style differs significantly by model family — using the wrong
  style for a model reduces quality noticeably.


  
SD 1.5 — Tag-based style

  
SD 1.5 was trained predominantly on short, comma-separated tag lists in the
  style of image-board metadata. This style still works best:

  

    

      Example positive prompt

      portrait of a knight, full armor, forest, golden hour, artstation, highly detailed, 8k
    

  

  
Quality booster tags that reliably improve SD 1.5 output:

  

    highly detailed
    artstation
    8k
    masterpiece
    best quality
    sharp focus
    cinematic lighting
    trending on artstation
  


  
SDXL & photorealism models — Natural language

  
SDXL and its fine-tunes (Juggernaut XL v9, Playground v2.5) were trained on
  captioned images with natural language descriptions. Write as if briefing a
  photographer:

  

    

      Example positive prompt

      A professional portrait of a woman in her 40s, natural makeup, soft studio lighting, Sony 85mm, shallow depth of field
    

  

  
Photorealism keywords that boost quality with SDXL fine-tunes:

  

    RAW photo
    DSLR
    85mm portrait lens
    shallow depth of field
    photorealistic
    skin pores detail
    natural lighting
    film grain
    catch lights in eyes
  


  
Flux — Photo caption style

  
Flux models understand prompts written exactly as you would describe a real
  photograph. Skip shorthand tags entirely and write in complete, descriptive
  sentences:

  

    

      Example positive prompt

      A fisherman in a yellow rain jacket standing on a dock at golden hour, salt-and-pepper mustache, weathered face, bokeh harbor lights in background
    

  

  
Flux handles text embedded in images (signage, book covers, labels) far
  better than SD or SDXL models — if you need legible text in the image, use a
  Flux model.


  
Negative Prompt


  
Describes what to exclude from the image. The negative
  prompt is effective for SD 1.5 and SDXL models. For Flux models, it is
  largely ignored — leave it blank when using Flux.


  

    

      Common negative prompt (SD 1.5 & SDXL)

      ugly, deformed, extra limbs, bad anatomy, blurry, watermark, text, low quality, oversaturated
    

  


  

    
Prompting tips

    
    
      
  • Match the prompt style to the model family. Tag-heavy prompts work well for SD 1.5; natural language sentences work better for SDXL and Flux.
    • 
      
  • Describe lighting explicitly. “Golden hour sidelight”, “soft overcast diffusion”, “dramatic Rembrandt lighting” all shift the output significantly across all model families.
    • 
      
  • Name camera and lens for Flux. Including specific gear like Sony A7IV, 85mm f/1.4 or Leica Q3 shifts the aesthetic noticeably.
    • 
      
  • Be specific about what you don’t want. For SD 1.5/SDXL, negative prompts like extra fingers, bad anatomy help avoid common artifacts in hands and faces.
    • 
      
  • Longer is fine for SDXL and Flux. Unlike SD 1.5, SDXL and Flux models have larger text encoders and respond well to long, richly detailed prompts.
    •

The sampler is the mathematical algorithm that
  progressively removes noise from the latent image across the denoising steps.
  Different samplers make different tradeoffs between speed, determinism, and
  creative variation. The scheduler controls the noise level

9 · Steps and CFG Scale


  
Steps


  
Steps is the number of denoising iterations the sampler performs. Each
  step refines the image further. More steps generally means a more refined,
  detailed result — but with diminishing returns above each model’s
  recommended range, and at the cost of generation time.


  

    

      
        

          Model family
          Recommended steps
          Notes
        

      
      
        

          Flux Schnell
          4
          Trained for exactly 4 steps — more steps do not help and can degrade quality
        

        

          Flux Dev
          20
          Up to 30 for very complex scenes; returns diminish above 30
        

        

          SD 1.5
          20–30
          20 is fine; 25–30 adds sharpness and fine detail
        

        

          SDXL / photorealism
          30
          25–40 for maximum detail; 30 is the sweet spot
        

      
    

  


  
CFG Scale (Classifier-Free Guidance)


  
CFG controls how strictly the model follows your text prompt versus
  exercising its own creative freedom. At low values the model interprets the
  prompt loosely; at high values it interprets it very literally, which can
  cause visual artifacts if taken too far.


  

    

      
        

          CFG Value
          Behavior
          When to use
        

      
      
        

          1.0
          Flux required Distilled guidance — the model handles steering internally.
          Every Flux model (Schnell, Dev Q4, Dev FP16) and Z-Image Turbo. The app auto-sets this.
        

        

          5 – 6
          Soft adherence Creative — the model interprets the prompt loosely.
          SD / SDXL when you want a softer, more atmospheric look or are exploring composition.
        

        

          7.0
          SD / SDXL default Balanced — the sweet spot for prompt-following without artifacts.
          Default for SD 1.5, Realistic Vision, SDXL Base, Juggernaut XL, Playground v2.5.
        

        

          8 – 10
          Literal Model follows the prompt very strictly; can start to oversaturate.
          When you need precise control over every detail. Stay below 10 to avoid artifacts.
        

        

          > 10
          Avoid Burnt, oversaturated, or colour-shifted output.
          Don't. If you're tempted to go this high, rewrite the prompt or pick a different sampler instead.
        

      
    

  


  

    
CFG and Flux — critical

    
Flux models use a guidance-distilled training approach that requires CFG
    to be set to 1.0. Setting CFG higher than 1.0 on a Flux
    model will produce overexposed, burnt, or colour-shifted images. The app
    auto-sets CFG to 1.0 when you select a Flux model — do not increase it.

  


  

    
Steps & CFG tips

    
    
      
  • CFG 7.0 is the right default for SD/SDXL. You can experiment with 5–6 for softer, more atmospheric results, or 8–9 for very literal prompt following — but stay below 10.
    • 
      
  • Flux Schnell at exactly 4 steps. Adding more steps is counterproductive — Schnell is distilled specifically for 4-step generation and does not benefit from additional steps.
    • 
      
  • Bump up SDXL steps for detail. Going from 30 to 35–40 steps with dpmpp_2m + karras on SDXL Base, Playground v2.5, or Juggernaut produces noticeably sharper fine detail in hair and fabric textures.
    • 
    

  







  
10 · Seed


  
The seed is an integer that initializes the random noise tensor used at
  the very first step of generation. Because the entire denoising process is
  deterministic given the same starting noise, the same seed paired with the
  same prompt and settings will produce an identical image every single time.


  

    

      Default value

      −1 (random)
    

    

      Reproducible result

      Any positive integer
    

    

      Seed range

      0 – 2 147 483 647
    

  


  
Workflow


  
    
    
  • Use −1 to explore. A new random seed is picked on every generation, giving you a different composition, lighting interpretation, and facial structure each time you click Generate. This is the best mode for early-stage exploration.
    • 
    
  • Lock a seed to refine. Once you find a composition or character you like, note the seed that produced it (shown in the status bar / generation output), and enter that exact number into the Seed field. You can now iterate on the prompt, CFG, or steps while keeping the same underlying spatial structure.
    • 
    
  • Small seed changes, large output changes. Seeds that are numerically close (e.g., 1000 and 1001) produce completely different images — they are not interpolations of each other.
    • 
    
  • Seed is model-specific. The same seed produces different images across different model checkpoints because the latent spaces differ.
    •

Stop


  
Clicking Stop sends an interrupt signal
  to the ComfyUI queue. Generation will halt at the next step boundary. A
  partially denoised image may or may not render depending on how far along the
  process was when the interrupt arrived. Use Stop if you realize your prompt
  needs adjustment and don’t want to wait for the full generation to
  complete.


  
Save Image…


  
Clicking Save Image… opens a system
  save dialog pre-populated with a descriptive filename that includes the model
  name, resolution, step count, and CFG value — for example:
  JuggernautXL_1024x1024_steps30_cfg7.0.png. Images are saved as
  PNG, which is lossless. You can save to any location on your system.


  

    
Unsaved images

    
Generated images are held in memory and displayed in the preview area.
    They are not automatically saved to disk. If you generate
    a new image without saving the current one, the previous result will be
    replaced. Save any image you want to keep before generating again.

  







  
12 · Per-Model Tips


  
  

    

      
SD 1.5 & Realistic Vision V6

      4 GB VRAM
      512×768
      Fast
    

    
    
      
  • Realistic Vision V6 is dramatically more photorealistic than vanilla SD 1.5. For any portrait or people photography intent, always choose Realistic Vision V6 over the base SD 1.5 model.
    • 
      
  • Add RAW photo keywords to the positive prompt: RAW photo, DSLR, photorealistic, skin pores detail significantly improves facial realism in Realistic Vision.
    • 
      
  • Use the negative prompt aggressively. Adding painting, illustration, cartoon, anime, 3D render prevents Realistic Vision from drifting toward illustrative styles.
    • 
      
  • 512×768 is ideal for portrait orientation. This matches the aspect ratio of typical portrait photography and stays close to the model’s native 512 px training resolution.
    • 
      
  • CFG 6–7 for faces. Slightly lower CFG (6.0–6.5) tends to produce more natural facial proportions and avoids the over-sharpened look that appears above CFG 8.
    • 
      
  • euler_ancestral gives more varied results than euler at the cost of being slightly less deterministic between runs with the same seed.
    • 
    

  


  
  

    

      
SDXL 1.0 Base

      8 GB VRAM
      1024×1024
      Moderate
    

    
    
      
  • Use natural language sentences, not tag lists. SDXL was trained on descriptive captions; tag-heavy prompts still work but produce slightly less cohesive compositions.
    • 
      
  • Add photorealistic for more realistic results, or deliberately omit it to lean into SDXL’s natural illustrative and graphic art strengths — SDXL Base has a distinctive stylized quality that is aesthetically strong for creative/artistic images.
    • 
      
  • 1024×1024 is the native resolution. Never generate SDXL at 512 px — the native training resolution is 1024 and quality degrades noticeably below 768 px on the short side.
    • 
      
  • Landscape 16:9 (1344×768) works well for wide scenes, architectural shots, and cinematic compositions.
    • 
    

  


  
  

    

      
Playground v2.5 & Juggernaut XL v9

      8 GB VRAM
      1024×1024
      Moderate
    

    
    
      
  • These are specialized photorealism fine-tunes of SDXL and produce dramatically more realistic results than SDXL Base for people, skin textures, and outdoor scenes.
    • 
      
  • Works exceptionally well with the Analyze → Prompt feature. The vision model generates photographic vocabulary (lens types, lighting descriptions, camera references) that these models are specifically trained to respond to.
    • 
      
  • For portraits: add shallow depth of field, 85mm portrait lens, skin pores detail, catch lights in eyes to the positive prompt to push the model toward its photorealistic strength.
    • 
      
  • Juggernaut XL v9 vs Playground v2.5: Juggernaut tends to produce better results for cinematic photoreal scenes; Playground v2.5 excels at stylized photo-art, color, contrast, and aesthetic compositions.
    • 
      
  • dpmpp_2m + karras is already auto-set — do not change the sampler/scheduler unless you have a specific reason to.
    • 
      
  • 35–40 steps pushes noticeably more fine detail into hair, fabric, and skin textures at the cost of ~5–10 extra seconds per generation.
    • 
    

  


  
  

    

      
Flux.1 Schnell / Dev / Dev FP16

      8–24 GB VRAM
      1024×1024
      Fast–Slow
    

    
    
      
  • CFG must be 1.0 — do not increase it. Flux uses guidance distillation; raising CFG above 1.0 burns and overexposes the output.
    • 
      
  • No negative prompt needed. Flux models largely ignore negative prompts. Leave the negative prompt field blank.
    • 
      
  • Write prompts as photo captions. Describe the image exactly as if writing a detailed caption for a real photograph: A macro photograph of a bee on a lavender flower, golden afternoon backlight, Sony FE 90mm macro
    • 
      
  • Flux handles text in images far better than SD/SDXL. If you need legible text rendered in the image (signs, book covers, labels, product packaging), use a Flux model.
    • 
      
  • Schnell for speed, Dev for quality. Use Flux Schnell Q4 for rapid iteration at 4 steps, then switch to Flux Dev Q4 or FP16 for final quality renders at 20+ steps.
    • 
      
  • Flux Dev FP16 is the highest quality model in LocalAI Studio. Use it only for final renders — it requires 24 GB VRAM and is significantly slower.
    • 
    

  

  

    

      
Z-Image Turbo

      12 GB VRAM
      1024×1024
      Fast
    

    
    
      
  • Keep CFG at 1.0. Z-Image Turbo is distilled like Flux-family models; higher CFG values waste VRAM and can degrade output.
    • 
      
  • Use natural-language prompts. Write a clear caption-style description instead of SD 1.5 tag piles.
    • 
      
  • Use the Turbo default step count. The catalog defaults are tuned for about 8 steps; adding many more steps rarely improves results.
    • 
      
  • Leave negative prompt blank. CFG-locked distilled families ignore or underuse negative prompts, so use positive phrasing instead.
    • 
    

  







  
13 · Troubleshooting


  

    

      
        

          Problem
          Solution
        

      
      
        

          ComfyUI shows "Not running"
          Click the Restart button in the status bar. If it still fails, run setup.bat from the LocalAI Studio installation folder to reinstall ComfyUI dependencies.
        

        

          "No checkpoints found" in the model dropdown
          No model files have been downloaded yet. Visit the Models tab and download at least one image model, then click Restart to reload ComfyUI.
        

        

          Image is grey / black / pure noise
          Wrong sampler or scheduler for the model — especially Flux models generated with karras or normal scheduler instead of simple. Select your model again from the dropdown to re-apply the correct defaults.
        

        

          Image is overexposed, washed out, or burnt
          CFG value is too high. For Flux models, set CFG to exactly 1.0. For SD/SDXL models, reduce CFG to 7.0 or lower.
        

        

          Flux model not appearing in the dropdown
          Flux GGUF models require the ComfyUI-GGUF custom node. Download the Flux model from the Models tab — it installs the required node automatically. Click Restart afterward.
        

        

          GGUF or Flux generation shows no progress for several minutes
          First-run GGUF dequantization, custom-node startup, or Flux compilation can be quiet even when ComfyUI is still working. Keep the job running unless the canvas reports a timeout/error or ComfyUI exits. Subsequent runs are usually faster after the support path is warm.
        

        

          "Analyze → Prompt" button is greyed-out or fails
          The selected vision model is not installed. Open the Models tab, install a Vision model such as Gemma 3, MiniCPM-V, or Llama 3.2 Vision, then return to Image Gen.
        

        

          Generation is very slow
          Try one or more of: (1) click Free VRAM and regenerate, (2) switch to a quantized model (e.g., Flux Dev Q4 instead of FP16), (3) reduce Steps (Flux Schnell at 4 steps is the fastest option), (4) reduce resolution using the SD 512 or SD 768 preset for SD 1.5 models.
        

        

          Out of memory / generation crashes
          The model requires more VRAM than is available. Click Free VRAM first, then try generating again. If it still fails, switch to a smaller model (Flux Schnell Q4 at 8 GB, or Realistic Vision V6 at 4 GB).
        

        

          Hands / fingers look deformed
          A common limitation of diffusion models. For SD/SDXL: add extra fingers, malformed hands, bad anatomy to the negative prompt. For Flux: add anatomically correct, natural human proportions, five fingers on each hand to the positive prompt. Changing the seed often helps too.
        

        

          Model doesn’t appear after dropping it into checkpoints
          ComfyUI must be restarted to scan for new files. Click the Restart button and wait for the status to return to Connected. The new model should then appear in the dropdown.
        

      
    

  








  
CPU mode for CPU-only systems

  

    
CPU OK means slow but usable

    
For machines without a dedicated GPU (integrated-graphics-only laptops and desktops), LocalAI can still drive a small set of image models on the CPU. CPU image generation is intended for explicitly cpu_viable SD 1.5-family catalog entries such as Realistic Vision and Counterfeit. Flux, SDXL, Z-Image, and other larger families still need a GPU for a good experience.

    
Expect long renders in CPU mode. The app shows CPU OK badges and a slow-render banner so users understand this is a compatibility path, not the fastest path.
