Overview

LocalAI Studio is a self-contained desktop application for Windows that lets you download, manage, and chat with open-source AI language models — and generate images locally using ComfyUI — completely offline after the initial download. No API keys, no subscriptions, no data leaving your machine.

  • Browse & download 48 curated built-in models (LLMs, vision, utility demos + image generation)
  • Live download progress & disk-space check
  • GPU acceleration (NVIDIA, AMD, Intel Arc)
  • Intel / Qualcomm / AMD NPU support via DirectML
  • CPU-only fallback mode
  • Real-time RAM, VRAM & CPU monitoring
  • Built-in streaming chat interface
  • Model delete on close (save disk space)
  • Batch benchmark mode (GUI & CLI)
  • Portable — copy folder to another PC
  • Full application log with filter levels

Software Prerequisites

Python 3.11+ (required)

The app is written in Python. setup.bat installs it automatically via winget. If you prefer to install manually:

Download: python.org/downloads
During install, tick "Add Python to PATH".

Ollama (required for GPU/CPU models)

Ollama is the engine that runs models on your GPU or CPU. setup.bat installs it automatically.

Manual download: ollama.com/download

ONNX Runtime DirectML (optional — NPU)

Needed only for the NPU/DirectML backend (Phi-3 ONNX models on your NPU). setup.bat (Windows) asks whether to install it, or run:
pip install onnxruntime-directml optimum[onnxruntime] transformers huggingface-hub

NVIDIA CUDA (optional)

Ollama auto-detects NVIDIA GPUs if the NVIDIA driver is installed. No separate CUDA toolkit install required — Ollama bundles its own CUDA libraries.

Installation

Everything is handled by a single script. Here is what happens step by step:

Windows Installation

1

Copy / extract the LocalAI folder

Place the LocalAI folder anywhere on your system (e.g., C:\LocalAI or your Documents folder). The app stores everything relative to this folder.

2

Run setup.bat

Double-click setup.bat. It will:
• Install Python 3.13 (if not present) via winget
• Install Python packages: customtkinter, requests, psutil
• Optionally install ONNX Runtime DirectML for NPU support
• Install Ollama (if not present) via winget

# Requires internet connection for first-time setup only
double-click setup.bat
3

Launch

Double-click run.bat. Ollama starts in the background automatically, then the LocalAI Studio window opens.

double-click run.bat
# or from a terminal:
cd C:\LocalAI
python main.py
Note: An internet connection is required only for the initial setup and for downloading models. Once a model is downloaded it runs 100% offline.

Manual Installation (advanced)

If you prefer to install dependencies yourself:

# 1. Install Python 3.13 from python.org (tick "Add to PATH")
# 2. Install Ollama from ollama.com/download/windows
# 3. Install Python packages
pip install customtkinter requests psutil

# 4. (Optional) NPU/DirectML support
pip install onnxruntime-directml "optimum[onnxruntime]" transformers huggingface-hub

# 5. Run the app
python main.py

Included Model Catalog

48 built-in models across chat, vision, image generation, speech, embeddings, and document AI surfaces, plus any models you add yourself via the + Add from Hugging Face button on the Models tab. All LLMs are quantised (Q4 or similar) to fit on modest hardware, and everything is downloaded on-demand — nothing is pre-installed. Every model has a dedicated Model Guide with recommended settings, click-to-copy demo prompts, sample renders, and per-card hardware fit.

Text generation

19 chat / reasoning models across four tiers — Ultra Small (3) for 4 GB RAM and below, Small (8) for AI PCs, Medium (5) for 8+ GB GPUs, and Extra Large (3) for high-memory GPU sessions.

Vision & multimodal

11 vision models including Llama 3.2 Vision, Florence-2 Base, Gemma 3 (4B / 12B / 27B), Qwen2.5-VL (3B / 7B / 32B), Mistral Small 3.2, MiniCPM-V, and Phi-4 Multimodal. Used by the Analyze → Prompt flow on the Image Gen page.

Image generation

11 image models from SD 1.5 / Realistic Vision (4 GB-friendly) all the way up to Flux.1 Dev FP16, plus SDXL Base, Juggernaut XL, Playground v2.5, Flux Schnell / Dev Q4, Z-Image / Turbo, SDXL Lightning, and a low-VRAM SDXL build.

Speech & utility

3 speech models (Whisper Large v3 Turbo CPU / GPU, SpeechT5 TTS), 1 embedding model (All-MiniLM), and 3 document AI utilities (Table Transformer, TrOCR Base / Large Printed).

See the full Model Guide. Every catalog model has its own card in the Model Guide with recommended settings, demo prompts, sample renders, and one-click hardware filters (hardware SKU chips, VRAM budget, intent / goal). The guide is the source of truth — this landing page just summarises what's in the box.
Storage tip: Language models are downloaded to Ollama's model cache (%USERPROFILE%\.ollama\models on Windows). Image generation models are stored in ComfyUI\models\checkpoints\ or ComfyUI\models\diffusion_models\ (GGUF Flux models). Make sure your drive has enough free space before downloading — the app checks automatically and will warn you.

NPU-Capable Models

The following models have ONNX versions and run on the NPU:

  • Phi-3 Mini 4K — microsoft/Phi-3-mini-4k-instruct-onnx
  • Phi-3.5 Mini — microsoft/Phi-3.5-mini-instruct-onnx
  • Phi-4 / Phi-4-mini ONNX bundles — require onnxruntime-genai-directml (their Grouped-Query-Attention KV layout breaks optimum.onnxruntime)

Select "NPU/DirectML (ONNX)" in the Chat backend dropdown before loading these models.

Phi-4 ONNX runtime note. Phi-4 bundles ship a genai_config.json and must route through onnxruntime-genai-directml (DirectML), onnxruntime-genai-cuda (CUDA), or plain onnxruntime-genai (CPU). The package variant determines the execution provider — there is no provider-string knob, and OpenVINO EP is not supported by onnxruntime-genai-directml. For CPU runs, the app prefers the CPU subfolder bundled in the same repository.

Using the Application

Models Tab

Browse the 48 curated built-in models, and extend the catalog yourself with + Add from Hugging Face on the Models page header — paste a Hugging Face URL (or an ollama: tag) and the dialog turns it into a SHA-pinned catalog entry without leaving the app. User-added rows show a (yours) badge and have a Remove from catalog button in the detail pane. Filter by category (Ultra Small / Small / Medium / Large / Extra Large / Vision / Image Generation / Speech / Embeddings / Document AI) or by hardware fit to see models matched to your available RAM and VRAM. Each card shows parameters, disk size, minimum RAM/VRAM, context length, and download status. Buttons available per model:

ButtonAction
DownloadPulls the model via Ollama (LLMs) or downloads the checkpoint file (image models). Shows live progress in the status bar.
Load & ChatLoads the model and switches to the Chat tab (LLMs only).
Generate ImagesOpens the Image Gen tab with the model pre-selected (image models only).
DeleteRemoves the model from local storage immediately. Works for both LLMs (via Ollama) and image generation models (deletes the checkpoint file).

Chat Tab

Select a backend (GPU/CPU, CPU only, or NPU/DirectML), load a model from the Models tab, then type messages and press Enter. Hold Shift+Enter for a newline. Press Stop to cancel mid-generation.

Not sure what to ask? Click the Prompt ideas link at the bottom of the Chat tab, or browse the Model Guide for showcase prompts tailored to every supported model.

Benchmark Tab

Run every selected text, ONNX, utility, and image-gen model without manual interaction. Pick the Benchmark profile matching your hardware (your local machine plus any SKU profiles you've defined in skus.json) to set the capacity used for default selections and runner filtering, then choose a Run mode:

  • Quick — one shared prompt per selected text/utility model. The fast smoke test you've always had; finishes in minutes for a small selection. Calibrated for ≤15 min on the smallest CPU-only SKU (the slowest supported profile): 17 chat / vision models on every SKU, plus one image row on GPU profiles (realistic-vision-v6 on entry-level GPUs, playground v2.5 on standard GPUs and up). Every default-ticked model is expected to pass.
  • Extended — iterates each model's curated sample prompts (three per chat/utility model) and, on GPU-capable profiles, generates a sample image for every default-ticked image-gen model. The Include image-gen models checkbox controls whether image runs are queued. Extended default-ticks every verified passer for the current SKU (sized to that SKU's chat/vision/utility/image budget). Extended takes longer but is still expected to pass for every ticked model.
  • Demo — runs a curated fast showcase subset: GPU profiles use GPU-only text and image rows, while CPU-only profiles use CPU-only text rows. Demo mode is intended for short, repeatable demos on cloud VMs without exercising the full catalog.

Models are grouped by category in collapsible banded cards — Ultra Small, Small, Medium, Large, Extra Large, Vision, Speech, Embeddings, Document AI, and (Extended/Demo on GPU profiles) Image Generation. Every card has a select-all checkbox in its header that toggles every eligible row in that category at once; rows the current profile can't run stay disabled and unchecked regardless. The Start / Stop / Retry Failed / Open Report Folder / Open HTML Report / Copy CLI Command buttons are pinned in a static bottom panel so they stay reachable even while the activity log grows during a long run. If your selection includes image-gen models and ComfyUI isn't running yet, the benchmark will start it automatically; if ComfyUI crashes mid-run, the runner restarts it once and retries the failed generation before moving on.

Reports are written as paired JSON + HTML in benchmark_results/. Click "Open HTML Report" for the themed results page with surface tabs (Text / Utility / Image / Failed), live status filter, embedded thumbnails with click-to-zoom, and a light/dark theme toggle. Both a per-mode latest_quick_benchmark.html/latest_extended_benchmark.html alias and the legacy batch_results.html alias are updated after every completed run. Click "Copy CLI Command" to get the equivalent command line (including --run-mode extended and --skip-image flags when applicable) for automation or scheduling.

Quick Start

1

Install ComfyUI

Run setup.bat and choose to install ComfyUI when prompted, or run it at any time from Settings → Install ComfyUI.

2

Download an image model

Go to the Models tab, filter by Image Generation, and click Get Model on a model. The app checks disk space first and shows download progress in the status bar. To remove a downloaded model, click Delete.

3

Generate

Click Generate Images on the model card, or open the Image Gen tab directly. Enter a prompt and click Generate.

Flux GGUF: Flux Schnell and Flux Dev Q4 require the ComfyUI-GGUF custom node and the gguf Python package — both installed automatically on first use along with the required CLIP encoders and VAE. GGUF models are stored in ComfyUI\models\diffusion_models\; standard checkpoints go in ComfyUI\models\checkpoints\.

Toolbox

The Toolbox tab is the user-facing surface for non-chat utility workflows. First runs may download model files and install Python packages; everything afterward runs locally on your hardware with no cloud calls.

Workflows

  • Transcribe — Whisper Large v3 Turbo on audio files
  • Read image text — Florence-2 / TrOCR best-effort OCR
  • Find tables — Table Transformer region detection
  • Speak — SpeechT5 TTS, WAV output
  • Search — All-MiniLM semantic snippet search
  • Describe — Florence-2 image captioning
One install or run at a time. Toolbox workflows are single-flight: only one install or workflow runs at a time so pip and Hugging Face downloads do not compete for the shared package directory or VRAM. Downloads land in .cache\huggingface by default (relative to the LocalAI install path), and the app honors an ambient HF_HOME if you set one.

What you'll see

The Toolbox page has a compact workflow browser on the left and a shared detail / result / activity panel on the right. Progress text and the final result area are kept separate, and each workflow exposes Open output and Open folder shortcuts for the files it generates.

Batch Benchmark Mode

LocalAI Studio includes a headless batch mode that automatically downloads, runs, and benchmarks every catalog model across every supported inference method (GPU, CPU, NPU/DirectML). It produces structured JSON and human-readable text reports showing which models your system can handle and how fast they run.

Running from the GUI

1

Open the Benchmark tab

Click Benchmark in the sidebar. Configure your test prompt, timeout, which inference methods to test, and optionally filter to specific models.

2

Click Start Benchmark

The benchmark runs model by model (smallest first), streaming progress into the output log. Press Stop at any time — the partial report is saved automatically.

3

View reports

When finished, click Open Report Folder to find batch_results.json and batch_results.txt in the benchmark_results/ directory.

Tip: Use the "Copy CLI Command" button to get the equivalent command-line invocation matching your current GUI settings. This is useful for scheduling benchmarks via Task Scheduler or running them on headless machines.

Running from the Command Line

Use run_batch.py directly for headless / automated benchmarking:

# List all available models
python run_batch.py --list-models

# Benchmark one small model (skip ONNX), 2-minute timeout
python run_batch.py --models qwen2.5:0.5b --skip-onnx --timeout 120

# Full benchmark of all models, save to a custom folder
python run_batch.py --output results/

# GPU only, clean up models after testing
python run_batch.py --skip-cpu --skip-onnx --cleanup

Or use the Windows launcher which auto-starts Ollama:

# Runs all models with defaults
double-click run_batch.bat

# With custom arguments
run_batch.bat --models phi3:mini phi3.5:mini --timeout 180

Report Output

Two files are produced after every run (including interrupted runs):

batch_results.json

Full structured data: every run result with model ID, method, timing (tokens/s, TTFT, total time, load time), response text, raw Ollama nanosecond stats, and a system resource snapshot.

batch_results.txt

Human-readable table with one row per run showing model, method, status, tokens/sec, time-to-first-token, total time, and token count. Includes a pass/fail summary at the bottom.

Timing Data

BackendSourceMetrics
Ollama Native nanosecond timing from the done=true response chunk total_duration, load_duration, eval_duration, eval_count, tokens/sec
ONNX Manual time.perf_counter() instrumentation Total time, time-to-first-token (TTFT), token count, tokens/sec

Execution Behaviour

  • Models are tested smallest-to-largest by disk size
  • A pre-flight hardware check skips models that exceed available RAM/VRAM
  • Models are downloaded automatically if not already local
  • Each run uses temperature=0.0 for deterministic output
  • Runs are wrapped in a per-model timeout (default 5 min)
  • The benchmark stops early after N consecutive failures (configurable)
  • Pressing Ctrl+C (CLI) or Stop (GUI) finishes the current run and saves a partial report
  • With --cleanup, models are deleted after testing to save disk space
Storage note: A full benchmark may need to download every model in the catalog. Ensure you have enough disk space (check the model table above) or use --cleanup to delete each model after testing.

Troubleshooting

ProblemSolution
Sidebar shows "Ollama not installed" Download from ollama.com/download/windows, install it, then restart the app. Or re-run setup.bat.
Download button is greyed out Ollama must be running. Check the sidebar status. If it says "Ollama not running", restart the app (it will try to start Ollama automatically) or start Ollama manually: ollama serve
"Not enough disk space" error Free up space on your drive, then try again. The app requires ~10% extra buffer above the model size.
Chat is very slow You are running on CPU. For GPU acceleration, ensure your GPU driver is up to date. Check the System tab to verify GPU detection. Select a smaller model for faster responses.
Task Manager shows only ~50% CPU usage during CPU-only chat (large multi-core systems) Not a bug — Ollama (built on llama.cpp) intentionally uses one thread per physical core, so on a 16-core / 32-thread CPU you'll see roughly half utilization with the other SMT (hyper-threaded) siblings idle. LLM inference is bound by the AVX / FPU execution units on each core, which are shared between SMT siblings, so forcing twice as many threads gives essentially zero speedup. Verified on a 16C/32T AMD EPYC VM with Llama 3.1 8B Q4: 14.32 tok/s at 16 threads vs 14.34 tok/s at 32 threads (OLLAMA_NUM_THREAD=32). The cosmetic graph is misleading — you're already getting full throughput, and overriding the thread count won't make generation faster.
NPU option has no effect Install ONNX Runtime DirectML (see NPU Setup section). The System tab shows whether DirectML is available.
App crashes on start Check LocalAI\localai.log for details. Most common cause: missing Python package. Re-run setup.bat.
Model load hangs forever The model may be larger than your available RAM. Press Stop, choose a smaller model, or close other applications to free memory.
Intel Arc / iGPU not used Ollama supports Intel Arc via SYCL. Ensure your Intel GPU driver is current (intel.com/download).
Ollama pulls fail with "no space left on device" even though the disk has plenty of room Some Windows machines have a size-capped user profile — common on corporate or managed devices and on any roamed profile setup. Once that profile fills with Ollama blobs, the next pull fails with OSError 28 / "no space left" even though Get-PSDrive shows hundreds of GB available. Relocate Ollama's models directory outside the profile by running the shipped helper set_ollama_models_dir.bat from your LocalAI folder. The helper defaults to <app path>\Ollama (a subfolder next to the LocalAI app itself) so blobs sit on whatever drive you installed LocalAI to — no hardcoded drive letter assumptions. 
# Easiest: run the shipped helper
cd path\to\LocalAI
set_ollama_models_dir.bat

# Or set it yourself at user scope (then restart Ollama)
setx OLLAMA_MODELS "C:\LocalAI\Ollama"
You can also change this from inside the app via Settings → Ollama Models Directory. The app writes OLLAMA_MODELS for you and warns if any of your three storage folders (Models, ComfyUI, Ollama) lives on a different drive than the app itself (acceptable, but if that drive disappears the models go with it). Important: OLLAMA_MODELS is consumed by the Ollama daemon, which is shared infrastructure — every other app on this PC that talks to Ollama (Open-WebUI, Continue.dev, other LLM front-ends) will also start reading models from the new location after the daemon restarts. The benchmark runner detects this disk-pressure failure mode and skips affected rows with an environment_skip failure phase so smaller models still run.
Setup or model download fails partway through with "No space left on device" v5.4.10 redirects every cache LocalAI touches (pip, Hugging Face, PyTorch, TMP, Ollama) into a .cache folder next to the app itself. If your home directory has a small quota or a roamed-profile cap, the install no longer needs to fit there. If you hit this on a previous version: re-run setup.bat (or fix_nvidia_pytorch.bat for the CUDA path, or fix_directml_pytorch.bat for the DirectML path on Intel / AMD / AI PC) from v5.4.10 — they prepend PIP_CACHE_DIR=%~dp0.cache\pip and friends before the first pip install so the multi-GB CUDA wheel lands on the install drive.
An earlier ComfyUI / Models / Ollama move was interrupted and now things look broken v5.4.10 adds a self-healing layer that runs at startup:
  • Resume / Roll back / Decide later dialog when a previous migration left a .localai-migration-state.json lock file (interrupted copy or verify phase).
  • Orphan-blob recovery when an Ollama directory contains blob files but no matching manifests — choose Recover (re-copies from the original location with full manifest ↔ blob cross-validation) or Discard (frees the space, irreversible).
  • Pre-flight free-space gate — refuses to start a migration unless the target drive has the full source size plus 10% headroom, with same-volume moves (metadata-only renames) recognised as zero-cost.
  • Cancel is always safe — pressing Cancel during a migration leaves your original files exactly where they were and removes the partial target.
Set LOCALAI_SUPPRESS_STARTUP_PROMPTS=1 to skip every self-healing prompt (used by the publish smoke-test gate; not needed by end users).

Portability — Moving to Another PC

Designed to be portable. Copy the entire LocalAI folder to a USB drive or network share and run setup.bat once on the new machine.

What travels with the folder

  • All application source code
  • Your config.json (settings)
  • ONNX model files (in LocalAI\models\)
  • The log file (localai.log)

What stays behind (must re-download on new PC)

  • Python and Python packages — re-run setup.bat
  • Ollama — re-run setup.bat
  • Ollama model files — stored in %USERPROFILE%\.ollama\models (Windows) (you can copy this folder manually if you want to avoid re-downloading)

Moving Ollama model cache (optional)

To avoid re-downloading large models, copy the Ollama model directory:

# Source PC: copy this folder to USB / network drive
%USERPROFILE%\.ollama\models

# Target PC: place it at the same path
C:\Users\<username>\.ollama\models

Uninstalling LocalAI Studio

To completely remove LocalAI Studio and restore your system to its pre-installation state, run uninstall.bat. It walks you through each component interactively — you choose what to remove. 

# Windows:
double-click uninstall.bat

Each step is optional — answer y to remove or n to skip.

2 Ollama downloaded models %USERPROFILE%\.ollama\models All LLM model files pulled via Ollama. Warning: shared by all Ollama apps.

  • Delete specific models from the Models tab (click Delete on each card)
  • Use Settings → Delete All Models to remove all Ollama models at once
  • Run cleanup.bat to remove dev/test files and caches without touching models or apps
